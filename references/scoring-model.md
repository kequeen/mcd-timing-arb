# 评分模型完整推导

本文说明引擎全部量化依据。所有参数均为显式常量，可在
`scripts/arb_core.py` 顶部调整。

## 一、为什么必须区分两个指标

初版设计把「资产价值随时间衰减」作为单一指标，结果被测试直接判负：

```
衰减(decay): 今日到期 → 0.12，  一周后 → 0.32，  远期 → 1.0
```

按这个模型，一张 ¥45 的券今天只值 ¥5.4。**这是业务上的错误。**

券不是慢慢贬值的。它是**悬崖式归零**：今天值 ¥45，明天值 ¥0。
「今天价值只有 12%」既不符合业务事实，也无法指导行动——它会让用户
以为「晚几天用也没差」，而这恰恰是最需要警告的场景。

修正后的模型把两个语义彻底拆开：

| 指标 | 类型 | 方向 | 参与金额计算 |
|---|---|---|---|
| `urgency` 过期压力 | 提醒强度 | 到期越近越大 | 否 |
| `decay` 兑现概率 | 行为概率 | 到期越远越大 | 是 |

## 二、过期压力 `urgency`

回答「现在要不要动」。从到期日反向指数增长：

```
urgency(d) = exp(-λ · d)        d < 0  →  1.0（已失效，100% 承压）
                             d ≥ 21   →  0.0（超出视野，不再打扰）
```

λ = **1/7** ≈ 1.4286e-1，选这个值让压力在有效视野内**平滑铺开**，
且 7 天时恰好降至 1/e ≈ 0.368，21 天降至 0.05。

实测值：

| 剩余天数 | urgency | 语义 |
|---:|---:|---|
| 0 | 1.000 | 今天必须动 |
| 1 | 0.867 | 紧急 |
| 2 | 0.751 | 紧急 |
| 3 | 0.651 | 本周内 |
| 5 | 0.490 | 本周内 |
| 7 | 0.368 | 可择时 |
| 10 | 0.240 | 可择时 |
| 14 | 0.135 | 暂缓 |
| ≥21 | 0.000 | 暂缓 |

*修正说明（两轮）：
1. 初版用幂函数 `1-(d/21)^2.2`，7 天与0 天的压力仅差 10%
   （1.0 vs 0.911），无法区分「今天必须用」与「本周内用」，
   被断言「一周后压力应显著低于今日」拦下。
2. 改用指数后初取 λ=ln(50)/21≈1.89，衰减过快——1 天掉到 0.15、
   3 天归 0.007、7 天已为 0，视野形同坍缩，"本周内"档位被压没。
   最终取 λ=1/7，每一档都有可区分度，且相邻档无平台期。

上表数值由 `test_arb_core.py` 第 2b 组断言锁定，防止再次回归。

**urgency 仅参与排序，绝不进入任何金额计算。**

## 三、兑现概率 `decay`

回答「这张券最终能不能真的被用掉」。随剩余天数**单调递增**并饱和：

```
decay(d) = P_MIN + (P_MAX - P_MIN) · (1 - exp(-d / τ))
```

| 参数 | 值 | 依据 |
|---|---|---|
| `P_MIN` | 0.68 | 今日到期：时间充裕，但确有忘掉的尾部风险 |
| `P_MAX` | 0.93 | 远期上限：仍留出「彻底遗忘」风险，不取 1.0 |
| `τ` | 8.0 天 | 兑现概率的爬升时间常数 |

实测值：

| 剩余天数 | 兑现概率 |
|---:|---:|
| 0 | 0.680 |
| 1 | 0.709 |
| 3 | 0.758 |
| 7 | 0.826 |
| 14 | 0.887 |
| 30 | 0.924 |

两个锚点都不取极值：0.68 而非 0（今天不是必然用掉），
0.93 而非 1.0（远期不等于必然兑现）。

## 四、风险敞口 `at_risk_value`

引擎的核心驱动量：

```
at_risk = face_value × (1 - decay)
```

含义是「现在不用就真会亏掉的钱」。

对照区分：

- `effective_value` = 面值 × decay →你**预期**能拿回多少
- `at_risk_value` = 面值 × (1−decay) → 你**可能**损失多少

示例数据（¥140 有效券）：

| 券 | 面值 | 剩余| 兑现概率 | 风险敞口 |
|---|---:|---:|---:|---:|
| 午餐立减 | ¥45 | 0 天 | 0.680 | ¥14.40 |
| 门店甜品券 | ¥12 | 1 天 | 0.709 | ¥3.49 |
| 早餐立减 | ¥18 | 2 天 | 0.737 | ¥4.73 |
| 第二份半价 | ¥25 | 5 天 | 0.799 | ¥5.02 |
| 周末双人餐 | ¥40 | 16 天 | 0.891 | ¥4.36 |
| **合计** | **¥140** | | | **¥32.00** |

注意反直觉之处：**¥45 的券风险敞口（¥14.40）远高于 ¥40 的券（¥4.36）**，
尽管面值更大。因为前者今天就到期，遗忘概率高得多。

## 五、最佳行动日 `best_action_day`

### 曾经的真实 bug

初版评分只考虑「当日活动增益 + 临近失效资产」，导致：

```
场景：¥45 券今日到期；两天后有 +¥22 的活动
初版输出：建议 10-17 去，"可叠加 ¥22 增益"
实际后果：¥45 已经归零，净收益 22 - 45 = -23
```

模型被活动增益**迷惑**，做出了净亏损决策。缺陷在于
完全没有惩罚「在候选日之前就已到期的资产」。

### 修正后的净收益

对每个候选日 `day`：

```
score(day) = Σ alive_value      # day 当天仍有效的资产（压力加权）
           + Σ campaign_value# day 当天的活动增益
           − Σ lost_before     # 在 day 之前就归零的资产（真实损失）
```

第三项是修正的关键。它让「让临期券归零去换活动增益」这一决策
在收益上永远不划算，除非活动增益确实大于归零损失。

### 边界行为验证

| 场景 | 输出 | 是否正确 |
|---|---|---|
| ¥3 券今日到期 + 两天后 +¥22 活动 | 选活动日 | ✅ 小额券值得等 |
| ¥45 券今日到期 + 两天后 +¥22 活动 | 选今天 | ✅ 不为小利丢大钱 |
| 远期券 + 三天后 +¥45 活动 | 选活动日 | ✅ 无临期压力 |
| 无资产 | 返回今天 | ✅ |

### 理由生成的口径

`action_day_rationale` 严格区分两个语义角色，避免误导：

- **收益项**只统计 `expires >= day` 的券——候选日还能用的才算收益
- **预警项**统计 `expires < day` 且**尚未过期**的券——提醒你更早用
- **已过期券两个项都不进**——它已经无法挽回，提醒「需更早使用」是错的

## 六、判定阈值

| 剩余天数 | 判定 | 文案 |
|---:|---|---|
| < 0 | 已失效 | 不再计入 |
| 0 | 今日必用 | 今天务必下单 |
| 1~2 | 紧急 | 今天或明天 |
| 3~7 | 尽快用 | 本周内 |
| 8~21 | 可择时 | 择活动日 |
| > 21 | 暂缓 | 等待更优窗口 |

## 七、参数敏感性

所有阈值都经过实测调整，非拍脑袋：

| 参数 | 变化 | 影响 |
|---|---|---|
| `URGENCY_RATE` | 调大 | 「紧急」范围收窄，更强调今天 |
| `P_MIN` | 调低 | 临期券风险敞口变大，警告更响 |
| `REDEMPTION_TAU` | 调大 | 兑现概率爬升更慢，远期券价值估得更保守 |
| 活动窗口 | 提前 | 最佳行动日前移|

模型对参数不敏感：主要结论（临期优先、活动让位于大额临期券）
在参数全区间内稳定成立。这是模型可信赖的依据。

## 八、已知局限

1. **兑付概率是启发式估计**，非历史统计拟合。当前没有足够的历史
   兑付数据支撑统计建模，参数取值来自业务常识与场景推演。
2. **未考虑券的叠加规则**：麦当劳部分券不可叠加，`stackable` 字段
   已在模型中预留但尚未参与计算。
3. **未接入门店维度**：不同门店可用的券不同，当前未按门店区分。
4. **活动增益为外部给定**：`estimated_gain` 需要人工或规则配置，
   引擎不自行推算活动能省多少。
